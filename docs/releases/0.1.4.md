# Frontend Quality Toolkit 0.1.4

## Summary

A security-hardening release. A full-repository security review found several ways a hostile web page could make the extension misbehave while you audit it. This release closes them, updates the development dependencies that had open `pnpm audit` advisories, and adds a validation suite that checks the numbers the toolkit reports against ground truth in a real browser.

There are no new features and no new extension permissions. Everything the extension did before still works.

## Security

- **No more requests to local-network addresses on a page's behalf.** Size probes, stylesheet fetches, asset downloads and thumbnails skip loopback, private, link-local and intranet hosts, and `file:` / `ftp:` targets. The exception is when the page you are inspecting is itself local, so auditing `localhost` still works.
- **Design-token values are validated before use.** A stylesheet could previously make the panel request an arbitrary URL through a token such as `hsl(...) url(...)`. Only plain colour values are now used as inline styles.
- **Linear-time CSS parsing.** A crafted 800 KB stylesheet could freeze the panel for minutes. The parser is now a linear scan.
- **Capped, streamed downloads.** Files are limited to 50 MB, a ZIP to 500 MB and a stylesheet read to 800 KB, counted on decoded bytes so compressed payloads cannot bypass the limit.
- **Locked-down messaging.** The service worker accepts messages only from the extension's own pages, validates tab ids and emulation sizes, and broadcasts can no longer name another tab.
- **Safer file names.** ZIP and download names are sanitised again at the archive boundary (Windows device names, trailing dots, runnable extensions).
- **Bounded full-page capture.** Width is capped at 20 000 px, as height already was at 40 000 px.
- **Less data in saved output.** Query strings and fragments are removed from saved screenshot metadata and from exported audit and `assets.json` page URLs. Markdown exports escape page-derived text.
- **Simulator frame.** The previewed site no longer receives clipboard access from the simulator iframe.

## Added

- `pnpm validate` and `pnpm validate:live`: a data-validity suite that compares reported results with independent measurements. It covers contrast ratios (checked against browser pixels), image, script and stylesheet byte sizes, breakpoints, a hand-derived CLS, TTFB, LCP, TBT and INP, and whether every reported selector resolves to one element. It uses two new fixtures, `tests/fixtures/truth.html` and `tests/fixtures/vitals.html`.
- Unit tests for the URL-safety rules and the other hardening changes.

## Changed

- Development tooling: `vitest` 5 and `puppeteer-core` 25 (clears the open advisories), `@types/node` added explicitly, the stale `package-lock.json` removed (the project uses pnpm), CI actions pinned to commit SHAs, Dependabot enabled, and ESLint now forbids `eval`-style APIs.
- The e2e scripts pass `pageUrl` when calling the size probe and CSS fetch, as the panel does, and the live-site runner reports the real error when the browser or page has already gone away.

## Compatibility

- Chrome 116 or newer (Manifest V3, side panel).
- Extension permissions are unchanged: `sidePanel`, `scripting`, `storage`, `debugger`, `declarativeNetRequest` and host access to all sites. See [PRIVACY.md](../../PRIVACY.md).
- Behaviour you may notice: when you audit a public site, asset thumbnails, size probes and downloads for resources that point at private-network addresses are now skipped instead of fetched.

## Known limits

Found by the new validation suite and not changed in this release:

- Inline script size counts UTF-16 characters, not bytes.
- The element count does not include shadow-DOM elements.
- First- and third-party detection treats hosts under multi-part suffixes (`co.id`, `github.io`) as the same site.

## Validation

- `pnpm lint`, `pnpm typecheck`, `pnpm test` (114 tests) and `pnpm build` pass.
- `pnpm e2e` passes on a real Chromium-based browser (Brave 155).
- `pnpm validate`: 107 of 110 checks pass, with 0 failures. The 3 warnings are the known limits above.
- Live-site runs (`pnpm e2e:prod`) pass for each site individually. Multi-site runs can lose the browser mid-session on some machines, so re-run a single site before treating it as a regression.
